# Prueba Funcional PF-02 — Creación de actividad con datos inválidos

- **Identificador:** PF-02
- **Épica origen:** E3 — Gestión de eventos *(evidencias visuales completadas en `evidencias/PF-02/` en E8-A)*
- **Requisitos asociados:** RF-05, RNF-02, RNF-08, RN-02, RN-03, RN-18
- **Responsable:** Integrante A
- **Herramienta utilizada:** Cliente HTTP HTTPS (`TestClient` sobre `https://testserver` en `tests/test_eventos.py`), SQLite, interfaz web y Swagger (`/docs`) sobre `https://127.0.0.1:8000`
- **Estado actual:** Ejecutada y aprobada (pruebas automatizadas y validación manual en interfaz web y Swagger con evidencias en `evidencias/PF-02/`)

## Condiciones iniciales

1. Base de datos SQLite temporal limpia sin filas en `eventos`.
2. Usuario organizador autenticado con cookie `pf04_session` y cabecera `Origin` válida.

## Casos cubiertos

### Caso PF-02.1 — Rechazo `422` ante fechas sin zona, rangos inválidos, cupo no positivo y campos extra
- **Método / Ruta:** `POST /api/v1/eventos`
- **Datos de entrada:** Seis solicitudes inválidas distintas:
  1. `fecha_inicio` sin zona horaria (`"2028-05-10T14:00:00"`).
  2. `cupo_maximo = 0`.
  3. `titulo` vacío tras recortar espacios (`"  "`).
  4. `fecha_fin <= fecha_inicio`.
  5. `fecha_limite_inscripcion > fecha_inicio`.
  6. Campo adicional no permitido (`extra="forbid"`).
- **Pasos:**
  1. Enviar cada carga útil inválida a `POST /api/v1/eventos`.
  2. Inspeccionar el código HTTP, la estructura del error JSON (`codigo`, `detalles`) y el conteo de filas en la tabla `eventos`.
- **Resultado esperado:** Todas las peticiones responden HTTP **422 Unprocessable Content** con `error.codigo == "ERROR_VALIDACION"`, sin exponer el campo `input` dentro de `error.detalles`, y con **0 registros persistidos** en `eventos`.
- **Resultado obtenido:** Todas las variantes devolvieron HTTP **422 `ERROR_VALIDACION`** sin clave `input` en `detalles` y con `COUNT(*) == 0` en SQLite (`tests/test_eventos.py::test_crear_evento_invalido_retorna_422_sin_persistir`), confirmado también manualmente en Swagger (`/docs`).
- **Estado:** Aprobada.

### Caso PF-02.2 — Rechazo visible en formulario web por rango de fechas inválido
- **Método / Ruta:** Vista `GET /organizador/eventos/nuevo` → `POST /api/v1/eventos`
- **Datos de entrada:** Sesión de `organizador` (`Carlos Ruiz`), título `"Evento invalido"`, fecha de inicio `15/11/2026 03:43 p. m.` y fecha de fin `15/11/2026 03:43 a. m.`.
- **Pasos:**
  1. Diligenciar el formulario de creación de evento en borrador con `fecha_fin` anterior a `fecha_inicio`.
  2. Enviar el formulario y observar la respuesta en pantalla.
- **Resultado esperado:** El servidor rechaza la creación con HTTP **422** y la UI muestra el error de validación sin registrar el evento.
- **Resultado obtenido:** La UI mostró la alerta `"Value error, La fecha de fin debe ser posterior a la fecha de inicio."` y no se creó ningún evento en `Mis eventos`.
- **Estado:** Aprobada.
