# Prueba Funcional PF-08 — Cancelación de inscripción y liberación de cupo

- **Identificador:** PF-08
- **Épica origen:** E5 — Inscripciones y control de cupos
- **Requisitos asociados:** RF-18, CA-04, RN-06, RN-07, RN-18
- **Responsable:** Integrante B
- **Herramienta utilizada:** Cliente HTTP HTTPS (`TestClient` sobre `https://testserver` en `tests/test_inscripciones.py`), base de datos SQLite y vista web `/mis-inscripciones`
- **Estado actual:** Ejecutada y aprobada en E5 (verificada con pruebas automatizadas e interfaz)

## Condiciones iniciales

1. Base de datos SQLite con evento publicado (`cupo_maximo = 5`, `fecha_inicio` en el futuro en UTC).
2. Un participante con inscripción en estado `activa` para dicho evento.
3. El participante está autenticado con cookie `pf04_session` válida.
4. Solicitud enviada sobre HTTPS con cabecera `Origin` válida.

## Casos cubiertos en E5

### Caso PF-08.1 — Cancelación oportuna antes del inicio del evento (`RN-07`, `CA-04`)
- **Método / Ruta:** `PATCH /api/v1/inscripciones/{inscripcion_id}/cancelar`
- **Condición temporal:** `ahora_utc() < evento.fecha_inicio`.
- **Pasos:**
  1. Verificar que la inscripción se encuentra en estado `activa` y que el catálogo muestra `cupos_disponibles == 4`.
  2. Enviar solicitud `PATCH /api/v1/inscripciones/{id}/cancelar` autenticado como el participante propietario.
  3. Inspeccionar respuesta JSON, base de datos y catálogo de eventos.
- **Resultado esperado:**
  - HTTP **200 OK** con esquema `InscripcionSalida`: `estado == "cancelada"`, `cancelada_en != NULL` en formato UTC.
  - La fila se conserva en la tabla `inscripciones` (no se realiza `DELETE`).
  - El cupo disponible en `GET /api/v1/catalogo/eventos/{id}` se recalcula de inmediato y **sube de 4 a 5**.
- **Resultado obtenido:** HTTP **200 OK**, marca temporal UTC registrada y cupo liberado verificado en `tests/test_inscripciones.py::test_cancelar_inscripcion_libera_cupo_y_persiste_cancelada`.
- **Estado:** Aprobada.

### Caso PF-08.2 — Rechazo de cancelación después del inicio del evento (`RN-07`)
- **Método / Ruta:** `PATCH /api/v1/inscripciones/{inscripcion_id}/cancelar`
- **Condición temporal:** `ahora_utc() >= evento.fecha_inicio`.
- **Resultado esperado:** HTTP **409 Conflict** con:
  ```json
  {
    "error": {
      "codigo": "CANCELACION_NO_PERMITIDA",
      "mensaje": "Solo puedes cancelar antes de que el evento haya iniciado.",
      "detalles": []
    }
  }
  ```
  La inscripción permanece en estado `activa`.
- **Resultado obtenido:** HTTP **409 `CANCELACION_NO_PERMITIDA`** confirmado en `tests/test_inscripciones.py::test_cancelar_inscripcion_despues_de_inicio_retorna_409`.
- **Estado:** Aprobada.

### Caso PF-08.3 — Rechazo de cancelación sobre inscripción ya cancelada
- **Método / Ruta:** `PATCH /api/v1/inscripciones/{inscripcion_id}/cancelar`
- **Datos de entrada:** Solicitud repetida sobre una inscripción que ya tiene `estado == "cancelada"`.
- **Resultado esperado:** HTTP **409 Conflict** (`CANCELACION_NO_PERMITIDA`) impidiendo transiciones redundantes.
- **Resultado obtenido:** HTTP **409** verificado en suite de pruebas.
- **Estado:** Aprobada.

### Caso PF-08.4 — Rechazo de cancelación de inscripción ajena (`Mínimo Privilegio`)
- **Método / Ruta:** `PATCH /api/v1/inscripciones/{inscripcion_id}/cancelar`
- **Datos de entrada:** Participante B intentando cancelar la inscripción que pertenece al Participante A.
- **Resultado esperado:** HTTP **404 Not Found** (`INSCRIPCION_NO_ENCONTRADA`) o **403 Forbidden** (`SIN_PERMISO`), impidiendo el acceso a recursos ajenos (defensa IDOR).
- **Resultado obtenido:** HTTP **404/403** verificado en `tests/test_inscripciones.py::test_cancelar_inscripcion_ajena_retorna_error`.
- **Estado:** Aprobada.

### Caso PF-08.5 — Reutilización inmediata del cupo liberado por otro participante
- **Flujo:** Tras la cancelación exitosa del participante A, un participante B se inscribe al evento que estaba lleno.
- **Resultado esperado:** La inscripción de B responde HTTP **201 Created**, demostrando la correcta liberación y reasignación del cupo.
- **Resultado obtenido:** Cupo reutilizado y validado en suite automatizada.
- **Estado:** Aprobada.
