# Prueba Funcional PF-11 — Consulta consolidada para coordinación y totales globales

- **Identificador:** PF-11
- **Épica origen:** E7 — Consolidado para coordinación
- **Requisitos asociados:** RF-24, RF-25, RF-26, RF-30, CA-06, RN-10, RN-19
- **Responsable:** Integrante B (documentación en E8-B)
- **Herramienta utilizada:** Cliente HTTP HTTPS (`TestClient` sobre `https://testserver` en `tests/test_reportes.py`), SQLite y vista web `/coordinacion/consolidado`
- **Estado actual:** Ejecutada y aprobada en E7 (verificada con pruebas de coherencia y permisos)

## Condiciones iniciales

1. Base de datos SQLite inicializada con múltiples eventos en distintos estados (`publicado`, `finalizado`, `cancelado`), con inscripciones activas, canceladas y asistencias marcadas (`presente`, `ausente`).
2. Usuario con rol `coordinacion` autenticado con cookie `pf04_session`.
3. Usuarios con roles `organizador` y `participante` para pruebas de restricción de acceso.

## Casos cubiertos en E7

### Caso PF-11.1 — Consulta del consolidado por coordinación (`CA-06`, `RF-24`)
- **Método / Ruta:** `GET /api/v1/reportes/consolidado`
- **Pasos:**
  1. Autenticarse como usuario con rol `coordinacion`.
  2. Enviar solicitud `GET /api/v1/reportes/consolidado`.
  3. Validar métricas de cada evento retornado en `items`.
- **Resultado esperado:**
  - HTTP **200 OK** con lista de eventos, cada uno reportando:
    - `cupo_maximo`, `inscripciones_activas`, `cupos_disponibles`.
    - `ocupacion_porcentaje`: calculado como `(inscripciones_activas / cupo_maximo) * 100`.
    - `total_canceladas`: historial de inscripciones canceladas.
    - `asistencias_presentes`, `asistencias_ausentes`, `asistencias_sin_registrar`.
    - `asistencia_porcentaje`: calculado como `(presentes / inscripciones_activas) * 100` (o `0.0` si no hay activos).
    - `estado_efectivo`: `publicado`, `finalizado` o `cancelado`.
- **Resultado obtenido:** HTTP **200 OK** con todas las métricas calculadas y tipos validados en `tests/test_reportes.py`.
- **Estado:** Aprobada.

### Caso PF-11.2 — Coherencia matemática de totales globales (`RF-26`)
- **Método / Ruta:** `GET /api/v1/reportes/consolidado`
- **Verificación:**
  - `totales.total_eventos == len(items)`
  - `totales.total_cupo == sum(e.cupo_maximo for e in items)`
  - `totales.total_inscritos_activos == sum(e.inscripciones_activas for e in items)`
  - `totales.total_canceladas == sum(e.total_canceladas for e in items)`
  - `totales.total_presentes == sum(e.asistencias_presentes for e in items)`
  - `totales.total_ausentes == sum(e.asistencias_ausentes for e in items)`
  - `totales.total_sin_registrar == sum(e.asistencias_sin_registrar for e in items)`
  - `totales.porcentaje_asistencia_global == round((total_presentes / total_inscritos_activos) * 100, 2)`
- **Resultado esperado:** Cuadre exacto al 100% entre la suma de cada columna y el objeto `totales` consolidado.
- **Resultado obtenido:** Coherencia matemática exacta verificada en `tests/test_reportes.py::test_coherencia_totales_globales_con_detalle_eventos`.
- **Estado:** Aprobada.

### Caso PF-11.3 — Filtros del consolidado (`RF-25`)
- **Método / Ruta:** `GET /api/v1/reportes/consolidado`
- **Parámetros probados:**
  - Filtro por rango de fechas: `fecha_desde` y `fecha_hasta` en formato ISO con zona.
  - Filtro por `tipo` (`conferencia`, `taller`, etc.), `modalidad` (`presencial`, `virtual`, `hibrida`), `estado` y búsqueda por `texto`.
- **Resultado esperado:** Filtrado correcto sobre los eventos retornados, recalculando los totales globales únicamente sobre los eventos coincidentes.
- **Resultado obtenido:** Filtros validados en suite automatizada.
- **Estado:** Aprobada.

### Caso PF-11.4 — Control de acceso por rol (`Mínimo Privilegio`)
- **Método / Ruta:** `GET /api/v1/reportes/consolidado` y `GET /api/v1/reportes/consolidado/csv`
- **Datos de entrada:** Peticiones enviadas por usuarios con rol `organizador` o `participante`.
- **Resultado esperado:** HTTP **403 Forbidden** con `error.codigo == "SIN_PERMISO"`. El consolidado es exclusivo del rol `coordinacion`.
- **Resultado obtenido:** HTTP **403 `SIN_PERMISO`** confirmado en `tests/test_reportes.py::test_acceso_restringido_solo_coordinacion`.
- **Estado:** Aprobada.

### Caso PF-11.5 — Exportación del consolidado a CSV (`RF-30`, `RN-19`)
- **Método / Ruta:** `GET /api/v1/reportes/consolidado/csv`
- **Resultado esperado:**
  - HTTP **200 OK** con cabecera `Content-Type: text/csv; charset=utf-8` y `Content-Disposition: attachment; filename="consolidado_eventos.csv"`.
  - Byte Order Mark UTF-8 (`\ufeff`) al inicio para compatibilidad con Excel.
  - Neutralización de inyección de fórmulas CSV: si algún campo de texto inicia con `=`, `+`, `-` o `@`, se precede con comilla simple `'`.
- **Resultado obtenido:** CSV exportado con cabeceras, formato y sanitización validados en `tests/test_reportes.py::test_exportacion_csv_formato_y_seguridad`.
- **Estado:** Aprobada.
